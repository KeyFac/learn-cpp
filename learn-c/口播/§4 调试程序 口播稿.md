# §4 调试程序 口播稿

---

同学们好，今天我们来讲**调试程序**。

写代码难免出错。这不是丢人的事——恰恰相反，**找bug**是程序员日常工作的一大部分。关键不在于"不犯错"，而在于如何高效地找到并修复错误。这个过程就叫**调试**。

今天我们就以 Dev-C++ 为例，来讲讲怎么用调试器来抓bug。

## 错误的三种类型

在学调试之前，我们先搞清楚我们会遇到哪几类错误。

**第一类：编译错误。**

就是代码语法写错了，编译器根本不让程序运行。比如少了个分号、括号没配对、变量名拼错。

这种错误最好修——编译器会告诉你哪一行出了什么问题，你照着改就行。在 Dev-C++ 里，编译错误会显示在下方信息面板，**双击错误信息**就能跳转到对应的代码行。

**第二类：运行时错误。**

程序能编译通过，但一运行就崩溃。比如除以零、数组越界、后面学指针时会遇到的空指针访问。程序要么弹个错误窗口，要么直接闪退。

**第三类：逻辑错误。**

这是最头疼的一种——程序能正常跑完，也不崩溃，但结果就是不对。比如应该用大于号的地方用了小于号，或者 `==` 写成了 `=`。

编译器不会报错，程序也不崩溃，但答案错了。

调试器主要就是用来对付**逻辑错误**和**运行时错误**的。

## Dev-C++ 的调试功能

好，那我们来认识一下 Dev-C++ 的调试功能。

调试相关的功能都在菜单栏的 **"调试"（Debug）** 里。

### 断点

先说**断点**。断点的意思就是：让程序在某个地方**暂停**，把控制权交给你。

设置断点很简单——点击代码行号左边的灰色区域，会出现一个红色圆点。取消也是点击它。

按 **F5** 启动调试，程序就会在第一个断点处停下来。

### 单步执行

程序停下来之后，你可以控制它一步一步地走：

- **F7（Step Over，单步跳过）**：执行当前行，跳到下一行。如果当前行调用了函数，不会进入函数内部。
- **Shift+F7（Step Into，单步进入）**：如果当前行调用了函数，会进到函数里面去看。
- **Ctrl+F7（Step Out，单步跳出）**：一直执行直到跳出当前函数。
- **Ctrl+F5（Continue，继续）**：继续运行到下一个断点。

初学者最常用的是 **F7**，一行一行地看程序是怎么执行的。

### 监视变量

这是调试最核心的部分——边跑边看变量的值。

按 **F4** 打开"添加监视"窗口，输入变量名，就能实时看到它的值变化。

更简单的方法是：调试状态下，把鼠标悬停在代码里的变量名上，Dev-C++ 会自动显示它的当前值。

## 调试实战

光说不练假把式，我们拿一个有bug的程序来实际走一遍调试流程。

```c
#include <stdio.h>

int main()
{
    int sum = 0;
    int i = 1;

    while (i <= 10)
    {
        sum = sum + 1;    // 本意是 sum = sum + i
        i++;
    }

    printf("1+2+...+10 = %d\n", sum);

    return 0;
}
```

这个程序想计算1加到10的和，但结果肯定不对。我们来调试。

**第一步：设断点。** 在while那一行左边点一下，设个红色断点。

**第二步：启动调试。** 按 Ctrl+F5，程序会在while那行停下来，左边出现一个黄色箭头。

**第三步：添加监视。** 按 F4，添加 sum 和 i 这两个变量。

**第四步：单步执行。** 按 F7，一行一行地走，同时看监视面板。

第一次按 F7，执行了 `sum = sum + 1`。这时 i=1，sum=1。这次碰巧对了，因为 0+1 确实等于1。

再按 F7，执行了 `i++`，i变成了2。

再按 F7，又回到 while 条件判断，`i <= 10` 为真，再次进入循环。

再按 F7，又一次执行 `sum = sum + 1`。看看监视面板——i=2，sum=2。

发现问题了吗？这次应该 sum = 1 + 2 = 3，但结果是2！因为每次只加了1，而不是加 i。

找到bug了——`sum = sum + 1` 应该是 `sum = sum + i`。

**第五步：修复验证。** 改好代码，取消断点，重新运行，看结果对不对。

## 几个实用技巧

**第一：条件断点。** 循环要跑100次，你只想知道 i=50 的时候发生了什么。右键点击断点，设置条件 i==50，程序只在满足条件时才停下来。

**第二：在监视里看表达式。** 不只能看变量，还能看表达式。比如输入 `i * 2`、`a > b`、`arr[0]` 这些。

**第三：什么时候 Step Into？** 调用 printf、scanf 这些库函数时，别 Step Into——会一头扎进一堆看不懂的底层代码。但你自己写的函数出问题时，一定要 Step Into 进去看。

## 常见问题

调试按钮是灰色的？确保你用的是 Ctrl+F5（开始调试），而不是直接点运行。

监视窗口看不到变量？检查变量名有没有拼错，还有变量是否在当前作用域内。

修改代码后调试没变化？记得重新编译再调试。

## 总结

好，我们来快速回顾一下今天的内容：

- **三种错误类型**：编译错误（好修）、运行时错误（崩溃）、逻辑错误（结果不对，调试器最常用）
- **断点**：让程序在指定位置暂停
- **单步执行**：F7 步过，Shift+F7 步入，Ctrl+F7 步出
- **监视变量**：F4 添加监视，鼠标悬停快速查看
- **调试流程**：设断点 → 启动调试 → 单步执行 → 观察变量 → 发现问题 → 修复

调试是一项练出来的技能。刚开始用可能觉得有点麻烦，但一旦习惯了，你找bug的效率会提升十倍不止。

遇到程序结果不对的时候，不要干瞪眼盯着代码发呆——**启动调试器，让它一行一行跑给你看**。
