# §4 调试程序

写代码难免出错。关键不在于"不犯错"，而在于**如何高效地找到并修复错误**。这个过程就叫**调试**。

## 错误的三种类型

在学会调试之前，先搞清楚我们通常会遇到哪几类错误。

### 1. 编译错误（Compile Error）

代码语法有问题，编译器根本不让程序运行。

```c
int a = 5
printf("%d", a);  // 错误！上一行少了分号
```

这种错误最好修——编译器会告诉你**哪一行出了什么问题**，照着改就行。

> Dev-C++ 中，编译错误会显示在下方信息面板里，**双击错误信息**可以跳转到对应的代码行。

### 2. 运行时错误（Runtime Error）

程序能编译通过，但一运行就崩溃。典型的有：

- **除以零**：`int a = 10 / 0;`
- **数组越界**：访问了不存在的数组元素
- **空指针访问**（学了指针后会遇到）

程序会弹出一个错误窗口，或者直接闪退。

### 3. 逻辑错误（Logic Error）

最头疼的一种——**程序能正常跑完，但结果不对**。编译器不会报错，程序也不崩溃，就是答案错了。比如应该用 `>` 的地方用了 `<`，或者 `==` 写成了 `=`。

> 调试器主要是用来对付**逻辑错误**和**运行时错误**的。

## 认识 Dev-C++ 的调试功能

在 Dev-C++ 中，调试相关的功能在菜单栏的 **"调试"（Debug）** 里。我们先认识几个最重要的概念。

### 设置断点（Breakpoint）

断点的意思是：程序运行到这里就**暂停**，把控制权交给你。

设置断点的方法：点击代码行号旁边的灰色区域，会出现一个红色圆点。

```
  行号
   1  │ #include <stdio.h>
   2  │ 
   3  │ int main()
   4  │ {
   5● │     int a = 10;     ← 红色圆点 = 断点
   6  │     int b = 20;
   7  │     int c = a + b;
   8  │     return 0;
   9  │ }
```

- 点击行号左侧的灰色区域可以设置/取消断点
- Dev-C++ 的快捷键：按 **Ctrl+F5** 开始调试，程序会在第一个断点处停下

### 单步执行

程序在断点处停下来后，你可以控制它一步一步地执行：

| 操作 | 快捷键 | 作用 |
|------|--------|------|
| **Step Over（单步跳过）** | **F7** | 执行当前行，跳到下一行。如果当前行是函数调用，**不进入函数** |
| **Step Into（单步进入）** | **Shift+F7** | 执行当前行，如果是函数调用就**进入函数内部** |
| **Step Out（单步跳出）** | **Ctrl+F7** | 一直执行直到跳出当前函数 |
| **Continue（继续）** | **Ctrl+F5** | 继续运行到下一个断点，或者直到程序结束 |

初学者最常用的是 **Step Over（F7）**——一行一行地看程序是怎么走的。

### 监视变量（Watch）

这是调试的核心——**边跑边看变量的值**。

打开"监视"面板：菜单栏 → **调试 → 添加监视**（或者按 **F4**）

在弹出的窗口中输入变量名，就可以实时看到它的值变化。

```
监视:
  a = 10
  b = 20
  sum = ?    ← 程序还没执行到这里，显示未定义
```

更方便的做法：在调试状态下，把鼠标悬停在代码中的变量名上，Dev-C++ 会自动显示它的当前值。

### 查看调用栈（Call Stack）

当程序遇到复杂函数调用时，"调用栈"面板会显示当前函数的调用路径——从 `main` 一路看到当前在哪个函数里。

## 调试实战：一步一步来

我们通过一个例子来体验完整的调试过程。

### 有问题的程序

```c
#include <stdio.h>

int main()
{
    int sum = 0;
    int i = 1;

    while (i <= 10)
    {
        sum = sum + 1;    // 这里本意是 sum = sum + i
        i++;
    }

    printf("1+2+...+10 = %d\n", sum);

    return 0;
}
```

这段代码的目的是计算 1+2+...+10，但结果不对。我们来调试找bug。

### 调试步骤

**第一步：设置断点**

在第8行（while 那一行）的行号左侧点击，设置一个断点。

**第二步：启动调试**

按 **Ctrl+F5** 开始调试。程序会在第8行停下来，左侧会出现一个黄色箭头指向当前行。

**第三步：添加监视**

按 **F4** 打开"添加监视"窗口，分别添加 `sum` 和 `i` 这两个变量。

**第四步：单步执行**

按 **F7**（Step Over）执行当前行。观察监视面板的变化：

```
初始状态：
  i = 1
  sum = 0

按一次 F7（执行了 sum = sum + 1）：
  i = 1
  sum = 1    ← 不对！应该是 sum = sum + i = 0 + 1 = 1，这次碰巧对了

再按一次 F7（执行了 i++）：
  i = 2
  sum = 1

再按一次 F7（回到 while，i <= 10 为真，进入循环体）
再按一次 F7（执行了 sum = sum + 1）：
  i = 2
  sum = 2    ← 这次应该 sum = 1 + 2 = 3，但结果是 2！
```

发现了！问题出在 `sum = sum + 1`——每次只加了1，而不是加 `i`。应该改成 `sum = sum + i`。

### 修复并验证

修改代码后，去掉断点（再次点击断点处），按 **Ctrl+F5** 重新运行，看结果是否正确。

## 高级调试技巧

### 条件断点

有时候循环要跑很多次，我们只想知道某个特定时刻的状态。Dev-C++ 支持条件断点：

右键点击断点 → 选择"断点属性" → 设置条件表达式。

比如循环 100 次，只想知道 `i == 50` 时发生了什么。

> 注意：Dev-C++ 的条件断点功能有限，复杂场景可能需要手动处理。

### 在监视中查看表达式

不只能看变量的值，还能看表达式。在监视窗口中输入：

- `i * 2` —— 看 i 的两倍是多少
- `a > b` —— 看条件是否为真
- `arr[0]` —— 看数组第一个元素

### 逐语句 vs 逐过程

- 当你调用 `printf`、`scanf` 这些库函数时，**不要 Step Into**，否则会一头扎进大量的底层代码
- 当你自己写的函数出问题时，**Step Into** 进去看看内部执行过程

## 常见问题

### 调试按钮是灰色的，用不了

原因：没有以调试模式编译。

解决方法：确保你点击的是菜单栏的 **"调试" → "开始调试"（Ctrl+F5）**，而不是直接点"运行"（F11）。Dev-C++ 在调试模式下会自动添加必要的调试信息。

### 监视窗口里看不到变量

- 确保程序正在调试中（已启动并在断点处暂停）
- 变量名不要拼错
- 变量要在当前作用域内（比如在循环外定义的变量，在循环内也能看；在循环内定义的变量，出了循环就看不了）

### 修改代码后调试没变化

每次修改代码后，**按 9 重新编译**，然后再调试。避免用旧的编译结果来调试。

## 本节小结

- **编译错误**：语法问题，编译器会提示
- **运行时错误**：程序崩溃，调试器可以帮我们定位崩溃位置
- **逻辑错误**：结果不对，这是调试器最常用的场景
- **断点**：让程序在指定位置暂停
- **单步执行**：F7 步过，Shift+F7 步入，Ctrl+F7 步出
- **监视变量**：F4 添加监视，鼠标悬停快速查看
- **调试流程**：设断点 → 启动调试 → 单步执行 → 观察变量 → 发现并修复问题

调试是一项**练出来的技能**。刚开始用调试器可能会觉得麻烦，但一旦习惯了这个流程，你会发现找bug的效率提升十倍不止。遇到程序结果不对，不要干瞪眼盯着代码发呆——**启动调试器，让它一行一行跑给你看**。
